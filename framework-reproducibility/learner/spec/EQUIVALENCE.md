# Совместимость результатов

Статус: консервативная основа; exact per-contract policy ещё не утверждена для scored run.

Проверяется наблюдаемое поведение, а не совпадение исходников или внутреннего package tree. Внешние имена/версии схем, HTTP method/path/status, query semantics, required vs optional, типы, nullability, evidence/confidence, resolution status, gaps, scope/revision и связи provenance являются контрактом.

По умолчанию сравнение строгое: JSON object key order незначим; порядок массивов, числовые типы, регистр строк, отсутствующее поле и null различаются. Это безопасный draft default, не доказательство того, что каждый массив в F4.95 упорядочен по публичному контракту. Любое ослабление требует отдельного review до scored run.

Не нормализовать глобально IDs, fingerprints, source spans, diagnostics, confidence, pagination totals, timestamps или revision references. Нельзя удалять неизвестные поля перед сравнением. Для implementation-local IDs возможна только заранее описанная взаимно-однозначная привязка с проверкой всей ссылочной структуры; такого normalizer в v0.1 нет. Если ID публично детерминирован, его алгоритм должен быть точно описан и значение проверено.

Массив разрешено сравнить как multiset только по явно утверждённому exact JSON Pointer для конкретного case. Дубликаты сохраняются. Нельзя сортировать все массивы: JOIN operands, expression sequence, source ranges и pagination могут зависеть от порядка. Comparator v0.1 поддерживает только это явное исключение; default policy не содержит исключений.

Представления времени и nondeterministic полей требуют отдельного контролируемого clock/run input или контрактного правила; «просто удалить поле» не допускается. Ошибки сравниваются по контрактным полям и статусам; точность текста диагностик ещё должна быть классифицирована по каждому endpoint.

Проверки обязаны различать: capability отсутствует; capability есть, данных нет; анализ не выполнялся; наблюдение не разрешено; coverage неполна; revision неизвестна. Ни одно из этих состояний не заменяется предположением об отсутствии факта.

CLI comparator оценщика находится вне learner pack. Его unit tests проверяют лишь механизм сравнения, не семантическую совместимость Framework.
