# AISL Attribute Lineage Explorer — установка чистой поставки

## Что это за приложение

Автономный браузерный просмотрщик готовых JSON-файлов AISL. Содержит режимы **«Обзор систем»**, **«Поток атрибутов»** и **«Паутина»** (выделение направленных входящих и исходящих цепочек). В архив уже включены синтетические примеры, которые можно открыть без доступа к AISL, GitHub или Nexus.

**На компьютере пользователя устанавливать ничего не нужно.** Достаточно поддерживаемого корпоративного браузера с доступом к внутреннему HTTP(S) адресу. Не нужен Elasticsearch, отдельный backend, база данных, Docker, Node.js или Python на клиентской машине.

## Развёртывание (для администратора внутреннего веб-сервера)

1. Создайте каталог на **уже действующем** внутреннем статическом HTTP(S) веб-сервере (Nginx, Apache или согласованный банком аналог), например `/srv/www/aisl-explorer/`.
2. Распакуйте **все файлы** этого ZIP в этот каталог с сохранением вложенного `demo/`. Не нужно запускать компиляцию, `npm install` или установщик.
3. Опубликуйте каталог по внутреннему адресу, например `https://intranet.example.local/aisl-explorer/`. URL — условный пример, замените его реальным адресом в вашем контуре.
4. Убедитесь, что веб-сервер возвращает `index.html`, `.css` как `text/css`, `.mjs` как `text/javascript` или `application/javascript`, `.json` как `application/json`; с корректным `Content-Type` и без принудительного скачивания JS.
5. Используйте обычную корпоративную HTTPS/TLS-конфигурацию и ограничение доступа на уровне существующего веб-сервера. **Приложение не содержит собственной авторизации.**
6. Рекомендуемые HTTP headers для каталога: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-cache` для `index.html`. CSP совместима с `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'none'; img-src 'self' data:; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'` (также присутствует meta CSP). При добавлении заголовка CSP на веб-сервере не ослабляйте политику.
7. Проверьте страницу в разрешённом корпоративном Chromium-совместимом браузере. Отключите доступ во внешний интернет и убедитесь, что вкладка работает и не выполняет внешних запросов.

**Важно:** запуск двойным кликом через `file://` не является штатным способом из-за ограничений модульного JavaScript. Нужен доступ по внутреннему `http://` или `https://` на существующем сервере.

## Как пользоваться

1. Откройте опубликованный внутренний URL. Автоматически появится встроенный **синтетический пример** (3 взаимодействия, 15 атрибутных маршрутов, 86 узлов, 77 связей).
2. Выберите режим **«Паутина»**, нажмите на любой узел: входящие и исходящие связи подсветятся, остальное станет менее заметным. Кандидатные межсистемные связи — пунктирные, не подтверждённые.
3. Перейдите в **«Поток атрибутов»** для подробностей, включая evidence/provenance и разрывы.
4. Для другого набора нажмите **«Загрузить JSON»** и выберите локальный файл. Поддерживаются `interaction-attribute-lineage/v1` (один результат) и `interaction-lineage-candidate-batch/v1` (пакет). Примеры доступны в `demo/lineage.json` и `demo/lineage-all-edges.json`.
5. Загруженные файлы обрабатываются **в памяти браузера**, без пересылки на веб-сервер или сохранения в localStorage/IndexedDB.

## Проверка целостности архива

Внутри находится `SHA256SUMS.json`: ожидаемый SHA-256 и размер **каждого** файла поставки (кроме самого манифеста во избежание рекурсии). Перед переносом в банк можно проверить целостность стандартным средством для SHA-256. Если файлы менялись или повреждены — пересоберите поставку из исходников, не исправляйте её вручную.

## Поддержка и ограничения

- Демонстрационные данные **синтетические**. Приложение не строит новые семантические связи: `candidate`, `gap`, `unresolved` и `terminal` не превращаются в `confirmed`.
- Оно не получает данные из GitHub/Nexus/AISL API, не обрабатывает исходный код и не использует LLM.
- Проверка в реальном банковском контуре, корпоративная лицензия/безопасность и доступность статического URL должны быть одобрены банком отдельно. Наличие ZIP не означает, что инфраструктурная приёмка уже выполнена.
- Лицензия собственного кода — MIT; внешний набор runtime/build зависимостей отсутствует. Подробности — `LICENSE`, `THIRD_PARTY_NOTICES.md`.

## Как пересобрать с нуля (только разработчику/CI, не конечному пользователю)

В репозитории `AndreyKorabelnik/aisl-application` есть повторно используемый скрипт:

```bash
python3 attribute-lineage-explorer/tools/build_clean_delivery.py --output /tmp/aisl-attribute-lineage-explorer.zip
```

Для тестирования в developer/CI среде с Node.js 20+:

```bash
cd attribute-lineage-explorer
node tests/test-core.mjs
node tests/test-web.mjs
```

Скрипт создаёт один воспроизводимый ZIP с фиксированными временны́ми метками ZIP-файлов, фиксированным порядком и allowlist ассетов, а затем сверяет его внутренние байты и манифест. Никакие сторонние пакеты не скачиваются; Node.js нужен только для тестов у разработчика.
